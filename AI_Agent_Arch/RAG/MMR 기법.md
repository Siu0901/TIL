# RAG 시스템 검색 품질 높이는 MMR 기법

랭그래프 위키 RAG 파트에 mmr 이거 있길래 첨보는 거여서 찾아봄. 책마루 챗봇에 이거 썼으면 좋았을 듯 함.

## 왜 있나
RAG 시스템을 구축할 때 코사인 등 단순 유사도 기준의 top-k 검색만 사용하면 좀 치명적인 문제가 발생할 수 있는데,
사용자의 질문과 의미적으로 가장 가까운 청크들을 가져오다 보니, **내용이 거의 동일하거나 중복된 문서들이 상위 순위를 독차지**하는 현상이 발생한다.
같은 책도 여러권 있는 도서관의 경우 도서 챗봇을 예시로 들면 '동물농장 비슷한 책' 했는데 1984만 10권 주는 꼴임.
LLM에게 똑같은 이야기만 반복해서 전달해, 답변의 다양성이 떨어지고 토큰 비용만 낭비하게 된다.

이 문제를 해결하기 위해 **질문과의 관련성**을 유지하면서도, **결과물 간의 다양성**을 동시에 확보하는 **MMR(Maximal Marginal Relevance)** 기법이 나오게 됨.

<br>

## MMR 공식 및 원리 이해

간단히 말하면 MMR은 아직 선택되지 않은 후보 문서들을 선택된 문서 바탕으로 차례대로 채점하여 가장 점수가 높은 문서를 하나씩 뽑아내는 반복 알고리즘이다.

$$MMR = \\arg\\max_{D_i \\in R \\setminus S} \\left[ \\lambda \\cdot Sim(D_i, Q) - (1 - \\lambda) \\cdot \\max_{D_j \\in S} Sim(D_i, D_j) \\right]$$

처음엔 수식 이해 안됬는데, 이 수식을 크게 두 개의 덩어리 **장점**과 **단점**로 쪼개서 보니 이해하기 아주 쉬웠음.

### 관련성 점수 (왼쪽 덩어리)
$$\lambda \\cdot Sim(D_i, Q)$$
얘는 현재 평가 중인 후보 문서($D_i$)가 사용자의 질문($Q$)과 얼마나 유사한지 측정하는건데, 그냥 코사인 유사도 같이 일반적인 유사도 말하는거다.
질문과 동떨어진 이상한 문서가 뽑히는 것을 방지하는 장점 점수임.

### 중복도 감점 패널티 (오른쪽 덩어리)
$$(1 - \\lambda) \\cdot \\max_{D_j \\in S} Sim(D_i, D_j)$$
현재 평가 중인 후보 문서($D_i$)와 **이미 선택된 문서들($S$)** 간의 유사도를 구한 뒤, 그중 **가장 높은 값($\\max$)**을 페널티로 부여한다.
쉽게 말하면 선택된 문서와 후보 문서간의 유사도 구해서 만약 높으면 문서가 중복된다는 거니까 해당 유사도 점수랑 관련성 점수랑 빼는 거임.

선택된 10개의 문서 중 9개와는 완전히 다른 내용이더라도, **단 1개의 문서와 내용이 100% 일치한다면** 중복 정보이기 때문에 합류시킬 가치가 없다. 따라서 유사도 점수가 높은 놈을 기준으로 감점을 때림.

### 하이퍼파라미터 $\lambda$ (람다)의 역할
* **$\lambda = 1.0$:** 중복도 패널티를 전혀 주지 않는다. 단순 유사도 검색(Top-K)과 동일하게 작동함.
* **$\lambda = 0.0$:** 질문과의 유사성은 무시하고, 이미 뽑힌 문서들과 가장 다르게 생긴 문서(다양성 극대화)만 찾음.
* **기본 권장값:** 보통 `0.5` 내외를 사용하며, 서비스 도메인의 특성에 맞게 튜닝한다.
도서/콘텐츠 추천이나 다각도 요약이 목적이라면 0.3~0.5 수준으로 다양성을 확보하는 것이 좋다함.

## 알고리즘 작동 방식

최종적으로 k=5개의 문서를 추출한다고 가정할 때, MMR은 다음과 같은 순서로 총 5번의 라운드를 돌며 결과 집합을 채워나간다.

1. **1차 후보군 확보 (`fetch_k`):** Vector DB에서 단순 유사도가 가장 높은 문서를 넉넉하게(대충 20개) 1차로 추린다. (전체 수만~수십만 개를 대상으로 반복 연산을 돌리면 리소스가 낭비되기 때문)
2. **1라운드 (1등 문서 선택):** 1차 후보군 중 질문과 유사도가 가장 높은 독보적 1등 문서(A)를 장바구니에 담는다.
3. **2라운드 (2등 문서 선택):** 남은 후보 문서들을 대상으로 MMR 공식을 돌린다. 질문과 적당히 비슷하면서도, **방금 뽑힌 문서 A와 가장 덜 겹치는** 문서(C)가 채택된다.
4. **3라운드 (3등 문서 선택):** 남은 후보들을 대상으로 다시 공식을 돌린다. 이번에는 **문서 A와도 안 겹치고, 문서 C와도 안 겹치는** 새로운 맥락의 문서(E)가 장바구니에 들어온다.
5. **반복:** 장바구니에 최종 목표치인 5개가 채워질 때까지 이 과정을 반복한다.

## 코드 적용

LangChain 환경에서는 리트리버 설정 시 `search_type="mmr"`을 지정해 주는 것만으로 딸깍할 수 있음.

```python
from langchain_community.vectorstores import Chroma

# Vector DB를 MMR 리트리버로 변환
retriever = vector_store.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 5,             # LLM에게 최종 전달할 청크 개수
        "fetch_k": 20,      # MMR 연산을 수행할 1차 후보군 크기
        "lambda_mult": 0.5  # 수식의 람다(λ) 값 (관련성 vs 다양성 균형)
    }
)
```
