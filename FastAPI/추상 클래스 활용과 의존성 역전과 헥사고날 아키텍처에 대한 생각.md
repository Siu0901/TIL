## 인스턴스 메서드 self와 클래스 메서드 @classmethod의 차이

이걸 왜 모르고 있었는지가 놀라울 지경임 ㄹㅇ

### self로 클래스 변수를 수정할 때의 햇갈린거

self로 클래스 변수를 수정하면, 원본이 바뀌는 게 아니라  
**그 객체만의 독립적인 인스턴스 변수가 새로 생성되어 덮어씌워진다.** 두둥탁

```python
class APIConfig:
    timeout = 10  # 공통 클래스 변수

    def change_with_self(self, new_time):
        self.timeout = new_time  # 클래스 변수 수정이 아님! (새 인스턴스 변수 생성한거임)

    @classmethod
    def change_with_cls(cls, new_time):
        cls.timeout = new_time   # 진짜 클래스 변수를 수정


conn1 = APIConfig()
conn1.change_with_self(30)

print(conn1.timeout)      # 30 (개인 변수)
print(APIConfig.timeout)  # 10 (원본은 그대로)
```
저렇게 self 쓰면 APIConfig이거에 적용이 안되고 conn1만 적용이 된다는 거임!!
확실히 초반에 클래스 관련된거 부실하게 하니까 이런 문제가 나타나는 것 같음. 시간 남을 때 다시 재복습 돌리자

### 대체 생성자  패턴

객체가 생성되기 전에 다양한 형태의 입력값을 처리해  
알맞은 인스턴스를 반환하는 요론것도 가능함

```python
import json

class UserSettings:
    def __init__(self, theme: str):
        self.theme = theme

    @classmethod
    def from_json(cls, json_str: str):
        # 객체를 만들기 전에 JSON을 파싱하고, 자기 자신을 호출해 객체 생성
        data = json.loads(json_str)
        return cls(theme=data['theme'])


# 일반 생성 vs 클래스 메서드를 통한 생성
user1 = UserSettings("dark")
user2 = UserSettings.from_json('{"theme": "light"}')
```

## 추상 클래스와 아키텍처

추상 클래스는 기능 구현이 목적이 아니라
**"이 기능을 만들 거면 무조건 내가 정해준 규칙을 따르라고 강제하는 설계도 역할**을 함

설명에 의하면 이는 헥사고날 아키텍처의 **포트** 개념과 완벽히 일치한다고 함!!.  
외부 기술(DB 등)이 바뀌어도 핵심 비즈니스 로직(Service)은 한 줄도 수정하지 않기 위해 사용한다.

### Port: 추상 클래스로 규격 정의

내부 로직이 외부에 요구하는 사항을 추상 클래스로 정의한다.

```python
from abc import ABC, abstractmethod
from typing import List

class VectorDBPort(ABC):
    @abstractmethod
    def search_books(self, vector: List[float]) -> List[str]:
        pass
```

### Adapter: 외부 인프라 구현체

위 규격을 상속받아 실제 DB에 연결한다.

```python
# 실제 동작하는 외부 시스템 (어댑터)
class PostgresVectorAdapter(VectorDBPort):
    def search_books(self, vector: List[float]) -> List[str]:
        # 실제 pgvector 쿼리 실행 로직이 들어가는 곳
        print("PostgreSQL에서 벡터 검색 실행")
        return ["AI 활용법", "파이썬 클린 아키텍처"]
```

### Core Service: 찐 비즈니스 로직

서비스 클래스는 실제 DB가 뭔지 모른 채,  
**오직 포트만 믿고** 로직을 전개한다.

```python
class BookRecommendationService:
    # 구체적인 클래스가 아닌 추상 클래스(Port)를 의존성으로 받음
    def __init__(self, db_port: VectorDBPort):
        self.db_port = db_port

    def recommend(self, user_vector: List[float]):
        # DB가 바뀌어도 이 코드는 절대 수정되지 않음
        books = self.db_port.search_books(user_vector)
        return [f"추천 도서: {b}" for b in books]
```

## 의존성 주입 조립하기

FastAPI의 라우터와 `Depends()`를 활용해 **런타임에 실제 어댑터를 서비스에 끼워 넣는다.**  
나중에 DB를 교체해야 한다면 `get_db_adapter` 함수 **딱 한 곳만** 수정하면 됨.

```python
from fastapi import FastAPI, Depends

app = FastAPI()

# 1. 의존성 조립 (어떤 어댑터를 쓸지 결정)
def get_db_adapter() -> VectorDBPort:
    # 나중에 Pinecone이나 다른 DB로 바꾼다면 여기서 return만 교체하면 됨
    return PostgresVectorAdapter()

# 2. 서비스 인스턴스에 어댑터 주입
def get_service(db: VectorDBPort = Depends(get_db_adapter)) -> BookRecommendationService:
    return BookRecommendationService(db_port=db)

# 3. API 라우터 (Inbound Adapter 역할)
@app.post("/recommend")
def recommend_books(
    user_vector: list[float],
    service: BookRecommendationService = Depends(get_service)
):
    return {"data": service.recommend(user_vector)}
```

## 정리

| 구성 요소 | 역할 | 변경 빈도 |
|---|---|---|
| **Port** (추상 클래스) | 계약서, 표준 플러그 규격 정의 | 거의 없음 |
| **Adapter** (구현체) | 실제 외부 기술 연결 (DB, API 등) | 기술 교체 시 |
| **Core Service** | 핵심 비즈니스 로직 | 요구사항 변경 시 |

- 자주 변하는 곳(**Adapter/DB**)과 중요한 핵심 로직(**Core/Service**)을 분리하자.
